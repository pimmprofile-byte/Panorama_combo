# 시나리오 인터페이스

`scenarios/<id>.py` 하나가 사건 하나입니다. 서버는 이 모듈을 `SC` 라는 이름으로
쥐고 판을 굴립니다. 여기 적힌 것이 그 사이의 계약입니다.

**좌석은 전부 사람입니다.** AI 배역이 없으니 연기 지시도 채점 프롬프트도 없고,
엔딩은 종막 지목표만으로 갈립니다.

**원칙 하나만 기억하면 됩니다 — 서버는 없는 속성을 전부 `getattr` 로 읽습니다.**
그래서 **안 쓰는 기능은 그냥 안 적으면 됩니다.** 아래 「선택」 표의 것들은
적는 순간 그 기능이 켜지고, 안 적으면 그 화면 자체가 안 뜹니다.

시작은 `scenarios/template.py` 를 복사하는 것입니다. 그 파일이 아래를 전부
최소한으로 구현해 둔 상태이고, 이대로도 판이 처음부터 끝까지 돌아갑니다.

## 1. 필수 — 없으면 안 돌아갑니다

## 3. `PHASES` — 막

```python
{"seq": 2, "key": "invest", "name": "1차 조사", "round": 1, "min": 14, "ap": 3,
 "quota": [{"label": "현장", "locs": ["A","B","C"], "n": 3}],
 "gm": "진행자가 읽는 지문."}
```

`key` 가 화면을 정합니다.

| key | 화면 |
|---|---|
| `open` | 오프닝 (비주얼노벨) |
| `invest` | 조사턴 |
| `talk` | 토론 |
| `accuse` | 1차 지목 — 비밀투표. `BELONGINGS` 압수와 `DEV_FROM_ACCUSE` 가 여기에 걸립니다 |
| `ask` | 질문지 (`ASK_SHEET` 필요) |
| `night` | 밤 (`NIGHT_ACTS` 필요) |
| `decision` | 갈림길 (`DECISION` 필요) |
| `escape` | 방탈출 (`ESCAPE` 필요). **`skipUnless` 로 통째로 건너뛸 수 있는 막입니다** — §8-a |
| `final` | 최후의 선택 — 답변 + 지목. **엔딩을 가르는 것은 지목 쪽입니다** |
| `reveal` | 진상 공개 |

같은 key 를 두 막에 쓸 수 있지만, **`final` 은 하나만 두세요** — 지목표를 받는
화면이라 두 자리에 있으면 먼저 온 막에서 지목이 끝나 버립니다. 방탈출을 판
중간에 끼울 때 `final` 이 아니라 `escape` 를 쓰는 이유가 그것입니다.

`round` 는 조사 라운드입니다 — 카드의 `round` 와 짝을 이룹니다. `ap` 는 그 막의
조사 횟수인데, 실제로는 `AP_BY_ROUND[round]` 가 판정에 쓰이므로 둘을 맞춰 둡니다.

**GM 지문에는 «판을 어떻게 굴리는가»만 적습니다.** 무엇이 수상한지, 누구에게
무엇을 물으라는 지시는 안 적습니다 — 그건 앉은 사람들의 몫이고, 대신 해주면
몰입이 깨집니다.

## 4. `CHARACTERS` — 배역

필수는 `id · name · job · color · tagline · persona · hidden · goals` 입니다.
나머지는 있으면 화면이 채워지고, 없으면 그 칸이 안 뜹니다.

| 키 | 어디에 뜨는가 |
|---|---|
| `hook` | 롤카드 첫 장. 1인칭으로 이 배역의 처지 |
| `storyPast` · `storyToday` | 「지난 과거」 · 「오늘, 일어난 일」 |
| `past` | `[{"w": 시각, "t": 일}]` — 「사건 당일, 나는」 타임라인 |
| `hide` | 감출 것. ★ 가 많을수록 치명적이라는 뜻으로 씁니다 |
| `goals` | `[{"t": 목표, "p": 점수}]` — 이 배역이 오늘 노리는 것 |
| `sins` | 이 배역의 죄. 진상 공개에서 읽어줄 몫입니다 |
| `tips` | 진행자 참고용. `private_sheet` 에서 내보낼지는 각자 정합니다 |
| `knows` | 판 시작부터 아는 카드 id |
| `look` · `known` | 인물 정보 화면 |

`hide` 가 이 판의 난이도를 실질적으로 정합니다. ★ 가 몇 개 붙었는지가 곧
「이게 나오면 얼마나 곤란한가」이고, 그게 그 사람이 얼마나 버티는지를 정합니다.

## 5. `CARDS` — 조사카드

필수는 `id · loc · locName · round · title · text` 입니다.

| 키 | 뜻 |
|---|---|
| `spot` | 구역 안 어느 자리인가. 현황판에 뜨는 이름 |
| `hint` | 이 카드로 무엇을 해야 하는지. **결론은 안 적습니다** |
| `reveal: "obligatory"` | 그 라운드에 저절로 전체공개 |
| `auto: True` | 뒤져서 못 엽니다 — 판이 때가 되면 엽니다 |
| `owner` | 그 배역은 이 카드를 못 엽니다 (자기 자신은 못 뒤진다) |
| `requires` | 먼저 밝혀져야 하는 카드 id |
| `combo: [id, id]` | 두 조각이 다 나오면 저절로 열립니다. 조사턴을 안 씁니다 |
| `gone: 3` | 3라운드부터 그 자리가 사라집니다 |
| `puzzle` | `{"prompt","answer","hint"}` — 수수께끼로 여는 자리. **`prompt` 만 화면에 나갑니다** |
| `puzzle.grants: "카드id"` | 풀면 **그 조사카드**를 준다. 도구가 아닌 퍼즐은 전부 이쪽입니다 — 퍼즐 한 장이 조사턴 값을 합니다 |
| `item: True` · `itemName` | 방탈출 도구. 인벤토리로 들어가고 손패 상한 밖입니다 |
| `keyHalf: True` | 입장권. 도구가 아니라 **막에 들어가는 몫**입니다 — §8-b |
| `startWith: 배역id` | 판 시작부터 그 배역의 인벤토리에 들어 있습니다 |
| `bait: True` | 미끼 카드 표시 |
| `hot: True` | 화면에서 붉게 |
| `shared: True` | 한 사람이 독점하지 않고 다 같이 봅니다 |
| `unlocks` | 이 카드가 여는 것 (`"pod"` 등) |

**본문에 판단을 적지 않습니다.** 보이는 것만 적고, 그게 무슨 뜻인지는
앉은 사람이 정합니다. `hint` 도 결론이 아니라 «이 카드로 무엇을 물어야 하는가»
까지만 적습니다.

## 6. 대화창에 줄을 흘려보낼 때

판이 스스로 하는 말(알리바이 · 막 머리 · NPC · 밤의 결과 · 소지품 반응)은
서버가 `drip` 표를 달아 내보내고, 클라이언트가 **줄 길이에 맞춰 한 줄씩** 답니다
(360ms + 글자당 20ms, 최대 1.9초). 사람이 친 말은 여기서 빠집니다.

대목이 바뀌는 자리에서 멈춰 세우고 싶으면 `ALIBI_LOG` 의 줄에 `"stop": True` 를
답니다. 대화창이 거기서 서고 「계속 ›」을 눌러야 이어집니다.

## 7. 붙이는 절차

1. `scenarios/template.py` → `scenarios/<id>.py` 로 복사
2. `ID` 를 파일 이름과 같게
3. `scenarios/__init__.py` 의 임포트 · `_MODS` · `_ORDER` 에 추가
4. 에셋 프롬프트를 쓸 거면 `pending/<폴더>/` 를 만들고 `server.py` 의
   `_ASSET_SETS` 에 한 줄
5. 로비와 관리자 화면은 `/api/scenarios` 를 읽어 저절로 집어갑니다 — 손으로
   적는 자리가 없습니다

## 8. 방탈출 · 개발자 — 엔진이 실제로 읽는 키 (server.py, 2026-08-05)

여기 적힌 것은 **전부 선택**입니다. 안 적으면 그 기능이 아예 안 뜹니다.

### 8-a. 조건이 안 차면 통째로 지나가는 막 — `skipUnless`

막(`PHASES` 의 한 항목)에 답니다. 고정 자리에 있지만 조건을 못 채우면 그 막은
**막 이름도 안 뜨고 지나갑니다** — 다음 막으로 바로 이어집니다.

```python
{"seq": 7, "key": "escape", "name": "방탈출 — 세상의 끝", …,
 "skipUnless": {"inventoryHas": ["E0", "G0"], "need": "all",
                "why": "열쇠 반쪽 둘이 모이지 않으면 경계에 문이 뜨지 않는다."}}
```

| 키 | 뜻 |
|---|---|
| `inventoryHas` | 이 카드들이 **누구의 것이든** 인벤토리에 있어야 합니다 |
| `need` | `"all"`(기본) · `"any"` · 숫자(그만큼만 있으면 됨) |
| `why` | 사람이 읽는 메모. 화면에는 안 나갑니다 |

`escape` 막에 `skipUnless` 를 안 적으면 열쇠 반쪽(아래)이 모였는지로 대신 봅니다.

### 8-b. 열쇠 반쪽 — 카드의 `keyHalf` · `KEY_HALVES`

도구가 아니라 **입장권**입니다. `item` 과 같이 손패 상한 밖(인벤토리)이지만,
공개되는 「도구 개수」에는 안 들어가고 문 앞의 조합 후보에도 안 섞입니다.

```python
{"id": "E0", …, "keyHalf": True, "itemName": "하늘 열쇠 반쪽"}
KEY_HALVES = ["E0", "G0"]      # 정본. 없으면 카드의 keyHalf 표시를 씁니다
```

### 8-c. `ESCAPE` — 문

엔진이 읽는 순서는 **① 잠긴 채로 열림 → ② 열쇠 장착 → ③ 문제 → ④ 열림/닫힘** 입니다.
성공도 실패도 못 푼 채로 넘어감도 **전부 다음 막으로 이어집니다.**

| 키 | 뜻 |
|---|---|
| `locked` | 막에 들어설 때의 한 줄. 기본 「세상의 끝... 이 보인다. 하지만 잠겨 있다.」 |
| `unlocked` | 반쪽 둘이 맞물렸을 때의 한 줄 |
| `intro` | 해금된 뒤 문틀을 설명하는 줄 |
| `slots` | `[{"id","label","note"}]` — 꽂는 자리 |
| `answer` | `{자리id: 카드id}` **★ 서버 밖으로 안 나갑니다** |
| `steps` | 문제를 직접 적을 때. `[{"id","kind":"tool"|"slot"|"code","prompt","note","answer"}]`. 안 적으면 아래 규칙으로 서버가 만듭니다 |
| `code` | `{"prompt","answer","require": True}` — `require` 를 켤 때만 마지막에 한 문제 더 붙습니다 |
| `tries` | 몇 번까지 틀려도 되는가. 기본 1(한 번 틀리면 닫힘) |
| `miss` | `tries` 가 2 이상일 때, 틀렸지만 아직 안 닫혔을 때의 줄 |
| `no` | 문이 닫힐 때의 줄 · `shut` 못 풀고 막을 떠날 때의 줄 |
| `ok` | 열렸을 때의 줄 |
| `bonus` | 성공 가점. **기본 5** — 좌석 전원에게 |
| `clear` | 클리어 정보. 열린 뒤 **전원**의 「추가 정보」로 갑니다 |
| `goals` | `{배역id: "그 사람의 새 1순위"}` — **그 사람 화면에만** 갑니다 |
| `keys` | 열쇠 반쪽을 여기 적어도 됩니다(`KEY_HALVES` 가 우선) |

**`steps` 를 안 적었을 때 서버가 만드는 문제** — `slots` 의 앞자리들은
「이 자리에 무엇을 꽂는가」(모은 도구 중에서 **고르는** 문제)이고, 마지막 한 문제는
「남은 것을 **어느 자리**에 넣는가」입니다. 도구 문제는 **자기 손에 있는 것만**
낼 수 있습니다.

**엔진이 내보내는 것** — 물음과 고를 것뿐입니다. `answer` · `code.answer` 는
어떤 응답에도 안 실립니다.

**엔드포인트** — `POST /api/escape/equip` (`roleId·clientId·cardId`) ·
`POST /api/escape/answer` (`roleId·clientId·pick`). 화면 몫은 `/api/state` 의
`escape` 에 실려 옵니다.

### 8-d. `DEV_FROM_ACCUSE` — 1차 범인지목으로 개발자가 정해진다

```python
DEV_FROM_ACCUSE = True
```

이 한 줄을 켜면, `accuse` 막의 표가 다 모인 자리에서 개발자가 정해집니다.

- 최다 득표자가 `DEV_PICK["pool"]` 안이면 → **그 사람이 개발자**
- 표가 갈리면(동표) → **아무도 안 들어옵니다**
- 최다 득표자가 `pool` 밖이면(지울 자아가 없는 자리) → **안 들어옵니다**

결과는 **그 사람 본인에게만** 갑니다 — `/api/state` 의 `dev`, 그리고
`/api/sheet/{배역}` 의 롤카드가 `DEV_PICK["sheet"]` 로 **갈아 끼워집니다**(덧붙지
않습니다). 남의 화면에는 그 칸이 아예 없습니다 — 「누구인가」는 물론
**「개발자가 들어왔는가」조차** 안 나갑니다. 대화창에도 사건 기록에도 안 남습니다.
`DEV_PICK["cut"]` 이 있으면 그 컷도 본인 화면에서만 재생됩니다.

---

### 8-e. 개발자 개입 컷 — `DEV_PICK["cutAll"]` · `["cut"]`

- `cutAll` — **모두가 보는** 컷의 `event_cut` 키. 개발자가 들어왔든 안 들어왔든
  지목이 끝난 자리에서 **똑같이** 한 번 돕니다. 안 적으면 공통 컷이 없습니다.
- `cut` — 개발자가 «된» 사람에게만 가는 컷. `/api/state` 의 `myCuts` 에
  **`cutAll` 과 같은 id** 로 실려서 그 자리를 갈아 끼웁니다(§10-a).

### 8-f. 채점을 서버가 어떻게 부르는가 (§9 의 짝)

- 화면에 나갈 문항은 `final_questions_public()` 을 그대로 씁니다 —
  `public_scenario()["finalQuestions"]` 도 서버가 이 결과로 덮습니다.
  **답안 배열의 순서는 이 결과의 순서**입니다(`draft` 는 빠져 있습니다).
- 답은 `/api/final-answers`(문항 순서대로의 문자열 배열)와
  `/api/quiz`(`{roleId, clientId, answers: {문항id: 선지id}}`) 둘 다로 받습니다.
  **받는 자리는 `FINAL_SHEET["answerSeq"]` 막부터**이고, 그 전에는 읽기만 됩니다.
- 셋이 다 내면 그 자리에서 걷고, 한 사람이 안 내도 그 막을 떠나면 걷습니다.
- 채점은 `score_final_answers(answers, dev_id)` 가 합니다. 서버는 거기에
  **개발자의 밑돈**(다른 둘의 «최종» 점수 합 — 방탈출 가점까지 포함)을 얹고
  `devScore["penalty"]` 를 빼고 `floor` 로 자릅니다.
- **결과는 `reveal` 막에서만** 열립니다(`/api/state` 의 `quiz.result`).
  그 전에 열면 개발자가 거기서 드러납니다.

## 9. 선지형 질문지의 «채점» — 시나리오가 내주는 계약

§10-b 가 **화면이 그리는 몫**이라면, 여기는 **점수를 세는 몫**입니다. 채점하는
사람이 없는 판이라 정답·배점은 전부 시나리오 안에 있고, 서버는 아래 두 함수만
부르면 됩니다. (구현 정본: `scenarios/rule_the_day.py`)

### 9-a. `FINAL_QUESTIONS` 의 dict 판본

```python
FINAL_QUESTIONS = [
  {"id": "q1", "q": "데이스트를 죽인 범인은?", "note": "하나만 고릅니다.",
   "options": [{"id": "damon", "label": "데이먼"}, {"id": "dayst", "label": "데이스트"}, …],
   "correct": ["damon", "dayst"],      # 여럿이면 중복 인정
   "bonus":   {"dayst": 1},            # 맞은 위에 더 얹는다
   "points":  6},
  {"id": "q2", …, "correctIsDev": True, "noDevKey": "none", "hitsDev": True, "points": 8},
  {"id": "q3", …, "draft": True},      # 아직 미정 — 화면에도 채점에도 안 들어간다
]
```

| 키 | 뜻 |
|---|---|
| `options` | `[{"id","label"}]`. **답으로 올라오는 것은 선지 `id`** 입니다 |
| `correct` | 정답 선지 id 목록. 여럿이면 중복 인정 |
| `bonus` | `{선지 id: 가점}` — 「더 깊이 본 답」에 얹습니다 |
| `points` | 맞히면 받는 점수 |
| `correctIsDev` | **그 판의 실제 개발자 배역 id 가 정답**. 개발자가 안 들어온 판이면 `noDevKey` 가 정답 |
| `noDevKey` | 개발자가 없는 판에서만 정답이 되는 선지 id |
| `hitsDev` | 이 문항이 **개발자의 점수를 깎는** 문항이다 |
| `draft` | 아직 안 정한 문항. **화면에도 채점에도 안 들어갑니다** |

`correct` · `bonus` · `points` · `correctIsDev` · `noDevKey` 는 **어떤 응답에도
안 실립니다.** 화면으로 나가는 판본은 아래 함수가 따로 만듭니다.

### 9-b. 함수 둘

| 이름 | 하는 일 |
|---|---|
| `final_questions_public()` | 화면에 나갈 몫. `{"id","q","note","options":[{"id","label"}]}` 만 남깁니다. `draft` 문항은 빠지므로 **답안 배열의 순서는 이 함수의 결과 순서**입니다 |
| `score_final_answers(answers, dev_id="")` | 채점 |

`public_scenario()["finalQuestions"]` 도 이미 이 함수의 결과입니다.

```python
score_final_answers(
    {"david": {"q1": "dayst", "q2": "damon"},   # 목록으로 줘도 됩니다: ["dayst", "damon"]
     "daisy": ["damon", "none"]},
    dev_id="damon")                              # 개발자가 없는 판이면 ""

→ {"points":  {"david": 15, "daisy": 6, "damon": 0},   # 개발자 몫은 여기서 0
   "hits":    {"q1": ["david", "daisy"], "q2": ["david"]},
   "devHits": 1,
   "devScore": {"base": "sum_others", "penalty": -20, "floor": None, "formula": …}}
```

### 9-c. 개발자의 점수 — `SCORE_RULES["dev"]`

**개발자는 자기 점수를 못 얻습니다.** 다른 두 사람의 «최종» 점수 합이 자기
점수가 되고, 개발자를 맞힌 사람 수만큼 고정 감점이 붙습니다.

```
개발자 점수 = 다른 두 사람의 최종 점수 합 − (맞힌 사람 수 × 20)
```

| 키 | 뜻 |
|---|---|
| `own` | 개발자가 자기 목표·퍼즐로 얻는 점수. `0` |
| `base` | `"sum_others"` — 밑돈은 다른 둘의 «최종» 점수 합입니다 |
| `penalty_per_hit` | 맞힌 사람 한 명당 고정 감점 (`-20`) |
| `hit_from` | 「맞혔다」를 어느 문항으로 보는가 (`"q2"`) |
| `floor` | 하한. `None` 이면 없음 |

`score_final_answers` 는 **감점만** 셈해 돌려줍니다 — 밑돈이 다른 둘의 «최종»
점수라 질문지만으로는 못 셉니다. 서버가 다른 둘의 최종 점수를 다 셈한 뒤
`devScore["penalty"]` 를 얹고, `floor` 가 숫자면 거기서 자릅니다.

개발자가 **안 들어온 판**(§8-d 의 동표·`pool` 밖)에서는 이 규칙이 아예 안
돌아갑니다 — 셋 다 자기 점수를 그대로 셉니다.

### 9-d. 언제 보여주고 언제 받는가 — `FINAL_SHEET`

```python
FINAL_SHEET = {"revealSeq": 9, "answerSeq": 10, "title": …, "intro": …, "rule": …}
```

`revealSeq` 막에서 **보여만 주고**(감점 규칙을 이때 공표), `answerSeq` 막에서
답을 받습니다. `public_scenario()` 에는 안 싣습니다 — 「지금 공개됐는가」는
`/api/state` 의 `finalSheet`(§10-c)가 정합니다.

## 10. 화면이 기다리는 것 — `index.html` 쪽 계약

여기 적힌 것은 **아직 안 오는 필드**입니다. 화면은 전부 «있으면 쓰고 없으면 예전대로»
로 만들어 뒀습니다 — 서버가 안 실어 보내도 지금 이대로 돌아갑니다. 이름을 맞춰
실어 보내면 그 순간 그 기능이 켜집니다.

### 10-a. 배역마다 다른 비주얼노벨 — `STATE.myCuts`

개발자 개입처럼 **당사자와 나머지가 다른 것을 보는** 막에 씁니다.

```jsonc
// /api/state 에 그 사람 몫으로만 실어 보냅니다
"cuts":   [{"id": "dev", "cuts": [ …컷… ]}],   // 방 전체가 받는 공통 컷 (지금도 있는 것)
"myCuts": [{"id": "dev", "cuts": [ …컷… ]}]    // 이 사람 몫. 같은 id 의 공통 컷을 «갈아 끼웁니다»
```

- 컷 하나의 모양은 `OPENING_CUTS` 와 같습니다 — `{"img","who","fx","focus","lines":[…]}`
- **id 가 같으면 덮어쓰고**, 공통에 없는 id 는 그 사람에게만 따로 재생됩니다
  (`night:mine:*` 이 이미 그렇게 돕니다)
- `myCuts` 가 없으면 예전처럼 공통 컷이 전원에게 그대로 돕니다
- 오프닝도 같은 규칙을 받습니다 — `STATE.myOpeningCuts` (없으면 `OPENING_CUTS`)

> **★ 갈래마다 컷 수와 재생 시간이 같아야 합니다.**
> 「개발자가 없는 판」에서 컷을 건너뛰면 **그 사실만으로 개발자가 없다는 게 전원에게
> 공지됩니다.** 화면만 보고는 어느 갈래인지 알 수 없어야 합니다 — 컷 수·줄 수·연출을
> 세 갈래가 같게 맞춰 주세요.
> 화면 쪽에도 안전판이 있습니다(공통 컷 수에 맞춰 자르거나 빈 컷으로 채웁니다). 다만
> 그건 **사고를 막는 것이지 설계가 아닙니다** — 걸리면 콘솔에 경고가 찍힙니다.

| | 당사자 화면 | 나머지 화면 |
|---|---|---|
| 누군가 개발자가 됨 | `myCuts` = 「덮어쓰기」 | 공통 = 「일렁임」 |
| 아무도 안 됨 | — | 전원 공통 = 「일렁임」 |

**§8-d 의 `DEV_PICK["cut"]` 을 내보낼 때 —** 그 컷을 `cuts` 에 «한 줄 더» 얹지 말고,
공통 컷과 **같은 id 로 `myCuts` 에** 실어 주세요. 얹으면 그 사람만 컷을 두 번 보게 되고,
그것만으로 「나에게 뭔가 있다」가 새어 나갑니다. 갈아 끼우면 재생 횟수까지 같아집니다.

### 10-b. 선지형 질문지 — `FINAL_QUESTIONS`

정본은 **§9** 입니다(정답·배점·채점). 화면은 그중 `final_questions_public()` 이
내주는 몫만 읽습니다 — 여기 적는 것은 **화면이 실제로 무엇을 보고 그리는가** 입니다.

| 화면이 읽는 것 | 없으면 |
|---|---|
| `q` (`text`·`t` 도 받습니다) | 문항 제목이 빕니다 |
| `options` (`choices`·`opts` 도 받습니다) | **선지가 없으면 예전 서술 입력으로 떨어집니다** |
| 선지 하나 — `{"id","label"}` 또는 그냥 문자열 | 문자열이면 id 와 이름이 같습니다 |
| `note` (`hint` 도 받습니다) | 문항 밑 한 줄이 안 뜹니다 |
| `draft: True` | 그 문항은 **화면에서도 빠집니다**(서버가 이미 걷어내지만 화면도 한 번 더 봅니다) |

- 목록이 문자열이면(지금 판본) 예전 서술 입력 그대로입니다 — **안 깨집니다**
- 답으로 올라가는 것은 **선지의 `id`**. `/api/final-answers` 의 `answers` 는 예전
  그대로 문자열 배열이고, **순서는 `final_questions_public()` 의 순서**입니다
- 선지 문항은 **하나도 안 비운 채로만** 제출됩니다(다 안 고르면 제출이 안 눌립니다)
- `correct` · `bonus` · `points` · `correctIsDev` · `noDevKey` 는 **절대 화면으로
  내보내지 마세요** — 화면은 받은 것을 그대로 그립니다

### 10-c. 질문지 공개 시점 — `STATE.finalSheet`

「2차 조사 뒤에 공개, 답은 종막에 확정」(작업목록 §7-g · 위 §9-d)을 화면이 이렇게 봅니다.

```jsonc
// 둘 중 아무 모양이나 받습니다
"finalSheet": {"open": true}
"finalSheet": {"revealSeq": 9, "answerSeq": 10, "rule": "…감점 규칙 한 줄…"}
```

- `open` 이 있으면 그게 정본입니다
- 없고 `revealSeq` 가 있으면 **그 막부터 `answerSeq` 앞까지**가 공개 상태입니다
- 둘 다 없으면 화면이 스스로 판단합니다 — **마지막 `invest` 막을 지났고 아직
  `final`·`reveal` 이 아니면** 공개된 것으로 봅니다(막 번호는 `PHASES` 에서 읽습니다)
- `rule` 을 주면 감점 규칙 문단이 그 문장으로 갈립니다. 큰 글씨 한 줄
  「내 점수가 남의 답에 따라 깎일 수 있습니다」는 **이 판의 압박이라 고정**입니다
- 공개 상태에서는 토론·갈림길 막 아래에 질문지가 **읽기 전용**으로 붙습니다 —
  고를 수 없고, 답은 `final` 막에서 받습니다

### 10-d. 조사 라운드 탭 — 라운드 수를 화면이 알아야 합니다

조사 현황이 **1차 / 2차 … 탭**으로 갈립니다. 라운드 수를 화면에 박아두지 않았고,
아래 순서로 읽습니다.

1. `SCEN.apByRound` — `AP_BY_ROUND` 를 `public_scenario()` 에 그대로 실어 보내면 이게 정본
2. `SCEN.phases[…].round` — 지금 `public_scenario()` 의 `phases` 에는 `round` 가 빠져 있습니다
3. 카드의 `round` — 위 둘이 없어도 이건 늘 옵니다(그래서 지금도 탭이 뜹니다)

`SCEN.roundNames = {1: "1차", 2: "2차"}` 를 주면 탭 이름이 그걸 씁니다(없으면 「N차」).
아직 안 열린 라운드 탭은 눌리되 「N차 조사에 열립니다」로 잠겨 보입니다.

### 10-e. 퍼즐카드의 열쇠 표시

`cardCatalog` 의 `locked`(= 카드의 `puzzle`)가 곧 「이건 수수께끼로 여는 자리」입니다.
화면은 그 한 값만 보고 현황판 칸·큰 화면·손패에 **열쇠 표시**를 답니다 —
따로 실어 보낼 것이 없습니다.
